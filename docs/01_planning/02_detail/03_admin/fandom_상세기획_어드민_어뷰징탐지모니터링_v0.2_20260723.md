## 1. 개요 및 비즈니스 목적

본 문서는 '팬덤 땅따먹기' 서비스의 공정한 경쟁 환경을 보장하기 위한 **실시간 이상 징후 핫스팟 모니터링, 동일 IP / Device Fingerprint 다계정 탐지, 4겹 어뷰징 방어 감시 대시보드 (`ADM-ABUSE-01`)**와 **상세 심사/보류 모달 UI/UX, 경고 발송 채널, 보류 이관 후속 워크플로우 및 어드민 공통 모달 매핑**을 초정밀 명세한다.

## 3. 상단 필터바 & 4대 위젯 정밀 데이터 명세

### 3.1 상단 글로벌 필터바 정밀 데이터 명세

| 필드명 | 라벨명 | UI 컴포넌트 타입 | 데이터 타입 / 포맷 | 디폴트 값 | 비고 및 이벤트 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `auto_refresh` | 실시간 자동 갱신 | Toggle + Select | Enum (`OFF`, `10s`, `30s`, `60s`) | `30s` | 선택 시 해당 주기마다 API 호출 |
| `date_range` | 모니터링 날짜 | Date Range Picker | Date (`YYYY-MM-DD`) | `Today` | 당일 ~ 최근 7일 |
| `risk_levels` | 위험도 레벨 | Multi-Select Dropdown | List (`HIGH`, `MEDIUM`, `LOW`) | `[HIGH, MEDIUM]` | 80점 이상 HIGH, 50점 이상 MEDIUM |
| `spot_search` | 성지 검색 | AutoComplete Input | String (Spot Name or ID) | `null` | 타이핑 시 성지목록 자동완성 |
| `fandom_id` | 팬덤 필터 | Dropdown | String (Fandom ID) | `ALL` | 등록된 팬덤 리스트 |

## 4. 4대 상세 모달 & 1대 드로어 정밀 UI/UX 명세

### 4.1 🔍 [모달 1] 핫스팟 세부 분석 모달 (Hotspot Detail Modal)
- **오픈 조건**: 위젯 2 핫스팟 지도 핀 또는 핫스팟 성지 리스트의 `[세부분석]` 버튼 클릭 시
- **화면 구성 명세**:
  - **Header**: `[핫스팟 상세 분석] 강남역 11번 출구 성지` (10분간 제출: **142건**, 평시: 5건, 폭증률: **+2,740%**)
  - **Body Left**: 10분간 1분 단위 인증 제출 추이 그래프 (Line Chart)
  - **Body Right**: 참여 유저 N명 팩트 대조 그리드 (닉네임, IP, 디바이스ID, 결제금액, GPS 거리, 승인 팩트)
  - **Footer Action Buttons**:
    - `[핫스팟 참여 유저 전체 주의 경고 발송]` -> **앱 푸시 (1차) + 이메일/마이페이지 배지 (2차) 동시 발송**
    - `[해당 핫스팟 영수증 전체 검수 보류 이관]` -> `MODAL-COMM-02` 호출 후 점수 유예 및 `ADM-SANCTION-02` 검수 큐로 이동

---

### 4.2 🔍 [모달 2] IP / 디바이스 차단 확인 모달 (`MODAL-ABUSE-IP-BAN`)
- **오픈 조건**: 위젯 3 테이블의 `[IP/기기 차단]` 버튼 클릭 시
- **화면 구성 명세**:
  - **차단 대상 정보**: Target IP (`192.168.12.44`) 또는 Device ID (`dev_89a7f1...`), 연관 계정 수 (6명)
  - **차단 범위 라디오 버튼**: `[x] 신규 가입 & 로그인 하드 차단`, `[x] 영수증 인증 제출 차단`
  - **차단 기간 선택 Dropdown**: `7일`, `14일`, `30일`, `영구 차단(PERMANENT)` (Default: `영구 차단`)
  - **차단 사유 입력 Textarea**: 차단 사유 입력 (예: 동일 IP 다계정 결제 도용 어뷰징 징후 확정)
  - **Footer Buttons**: `[취소]` / `[IP/기기 차단 확정]` (클릭 시 DB 차단 블랙리스트 등록 및 어드민 Audit Log 저장)

---

### 4.3 🔍 [모달 3] 수동 검수 보류 확정 모달 (`MODAL-COMM-02`) — *공통 재사용 모달*
- **오픈 조건**: 위젯 3 테이블의 `[보류 이관]` 버튼 클릭 시
- **화면 구성 명세**:
  - **보류 이관 대상 요약**: "선택된 IP 그룹의 **6개 계정**, **14건의 영수증 인증 건**을 수동 검수 큐로 이관합니다."
  - **보류 사유 선택 Select**: `동일 IP 다계정 결제 징후`, `GPS 위치 오차 과다`, `영수증 승인번호 패턴 유사`
  - **점수 유예 체크박스**: `[x] 검수 완료 전까지 해당 건들의 점유율/랭킹 점수 반영 일시 유예`
  - **운영자 처리 메모 Textarea**: 운영 메모 입력 (최대 500자)
  - **Footer Buttons**: `[취소]` / `[보류 이관 확정]` (클릭 시 `ADM-SANCTION-02` 수동 검수 큐로 데이터 전송)

---

### 4.4 🔍 [모달 4] 토스트 딥링크 — 상세 심사 원스톱 모달 (`MODAL-ABUSE-TOAST-REVIEW`)
- **오픈 조건**: 어드민 상단 Alert 토스트 (`Risk Score >= 80` 감지 시) 클릭 시 딥링크 오픈
- **화면 구성 명세**:
  - **Header**: `[이상 탐지 긴급 심사]` - 감지 유형: **동일 Device 6계정 연속 인증** (Risk Score: **90점**)
  - **조사 담당자 배지**: **`[조사 담당: admin_01 (자동 지정)]`** (모달 오픈과 동시에 `NEW` -> `UNDER_INVESTIGATION` 으로 자동 업데이트되어 타 어드민 중복 처리 방지)
  - **Body**: 연관 유저 6명 닉네임 목록, 결제 영수증 캡처 팩트 뷰어, GPS 제출 마커 맵
  - **Footer 원스톱 버튼 3종**:
    - `[1. 정상 판명 (RESOLVED)]`: 이상 없음 확인, 상태 `RESOLVED` 변경 후 종결
    - `[2. 수동 검수 이관 (PENDING_REVIEW)]`: `MODAL-COMM-02` 모달 호출 후 검수 큐로 이관
    - `[3. 즉시 제재 부여 (SANCTIONED)]`: `MODAL-COMM-01` 공통 제재 모달 호출

### 4.5 🔍 [드로어 1] Device & IP Fingerprint 상세 Drawer
- **오픈 조건**: 위젯 3 테이블의 `[상세 핑거프린트]` 버튼 또는 IP/Device ID 클릭 시 우측 400px 슬라이딩 오픈
- **화면 구성 명세**:
  - **Top Summary**: IP (`192.168.***.***`), Device Fingerprint Hash (`dev_89a7f1...`), `Risk Score: 85점 (CRITICAL)`
  - **Section 1 (속한 회원 목록)**: 6명 회원의 프로필 썸네일, 실명, 닉네임, 가입일, 현재 계정 상태 배지
  - **Section 2 (1:1 영수증 & GPS 대조)**: 제출 영수증 캡처 대조 뷰어, 지도 위 GPS 마커 겹침 현황
  - **Bottom Fixed Buttons**: `[IP/기기 차단]` (`MODAL-ABUSE-IP-BAN` 호출) / `[그룹 전체 수동검수 이관]` (`MODAL-COMM-02` 호출)

# 메인 지도 · 점령보드 · 랭킹 컨셉 전환 지시서 (v0.2)

> 대상 파일: `docs/02_design/02_userview_v0.4/fandom_userview_v0.4_20260817.html`
> 대상 화면: `UV-MAIN-01`(메인 성지 지도), `UV-MAIN-03`(주변 성지 바텀시트), `UV-SPOT-04`(성지 제보 모달), `UV-VERIF-02`(가산옵션 점수 체계), `UV-WAR-01`(영토 전황 보드), `UV-RANK-01`(랭킹 보드 메인), `UV-RANK-02`(개인 기여도 상세), 하단 탭바 전반

## 1. 배경 (방향 전환 이유)

현재는 "땅따먹기(영토 점령)"가 서비스 전면에 나서 있는데, 이 컨셉을 그대로 메인으로 밀면 유저에게 부담스럽게 느껴질 수 있음. 아래처럼 우선순위를 조정함.

- 1순위 프레임: "내가 좋아하는 아티스트가 다녀간 곳에, 나도 다녀왔다" — 개인적 팬심/순례 경험
- 2순위(부산물): 이 개인 인증들이 쌓이면 자연스럽게 영토 점령처럼 보인다 — 즉 정복 게임이 아니라 "최애의 발자취를 따라가는 순례"가 메인 정체성이고, 땅따먹기는 그 결과로 드러나는 서사

이 방향을 구체화하는 과정에서, 하단 탭 3개(지도/점령보드/랭킹)의 역할이 서로 겹치는 지점이 있다는 걸 확인했고, 아래처럼 역할을 명확히 재정의함.

## 2. 지도 · 점령보드 · 랭킹 역할 재정의

| 구분 | 지도 | 점령보드 | 랭킹 |
|---|---|---|---|
| 니즈 | 최애와 같은 공간에 있고 싶다 / 오늘 어디 가지? (친밀감·소속감 + 발견 욕구) | 우리 팬덤이 잘하고 있는지 확인하고 싶다 (팬덤 자부심·소속감 + 경쟁심) | 내 노력을 인정받고 싶다 (개인 성취감·인정 욕구) |
| 핵심 질문 | 내 최애 발자취를 얼마나 따라갔나 | 지금 이 순간 어디를 누가 차지했나 | 지금까지 누가 제일 잘했나 |
| 주인공 | 나 + 내 최애 (1인칭) | 우리 팬덤 vs 다른 팬덤 (집단) | 개인(사람) |
| 시점 | 개인적 · 발견/탐색 | 실시간 스냅샷 | 누적 (+기간 필터: 전체/주간) |
| 핵심 콘텐츠 | 성지 핀(방문·미방문, 실제방문지·팬커뮤니티성지 타입 구분), 주변 성지 리스트, 팬덤 필터 | 구별 점령 4색 지도, 뒤집힘 타임라인, 경합구 Top3 | 개인 TOP N 리스트, 내 순위, 개인 기여도 상세(뱃지·구별 지분율) |
| 제외/삭제 | 구별 점령 색칠 (완전 제거, 토글도 두지 않음 — 그 역할은 점령보드가 전담) | — | 팬덤 서브탭 제거 (팬덤 간 비교는 점령보드가 이미 공간적으로 담당) |
| 계산 기준 | — (개인 기록 표시일 뿐, 별도 스코어링 없음) | 구 점유율 = 구 내 팬덤별 인증 건수 비율 | 개인 누적점수 = 인증 조합점수(1.0~2.5) + 실제방문지 보너스(+1점) 등 |
| CTA/톤 | "발자국 남기기" — 감성적, 동행형 | "기여하러 가기" — 경쟁적, 게임 언어(역전/점령) 허용 | 성취/명예 톤, 뱃지·순위 중심 |
| 무소속 유저(최애 미지정) | 탐색모드(전체 팬덤 성지 인기·거리순 혼합 노출) | 그대로 열람 가능(관전 목적) | 그대로 열람 가능(관전 목적) |
| 하단 탭바 명칭 | "지도" 유지 | "점령보드" 명칭 유지 (경쟁 정체성을 이 탭이 전담하므로 개명 불필요) | "랭킹" 유지 |

세 탭이 "발견(지도) → 경쟁(점령보드) → 성취(랭킹)"로 층위가 나뉘고, 겹치는 데이터가 없어짐.

## 3. 지도(UV-MAIN-01) 세부 변경사항

### 3-1. 지도 기본 레이어
- 기존: 25개 구 GeoJSON 폴리곤을 DOMINATED/COMPETING/NEUTRAL/REVERSED 4색으로 항상 칠해서 보여줌
- 변경: 구 단위 진영 색칠은 지도 탭에서 완전히 제거 (토글도 없음 — 점령보드 탭으로 역할 이관)
- 대신 "내가 선호하는 아티스트가 다녀간 성지" 핀을 지도 위 기본 요소로 표시. 핀은 방문/미방문 상태 구분 필요 (예: 채워진 핀 / 빈 핀, 채도 차이) → "내 성지순례 도장판" 같은 느낌

### 3-2. 성지 타입 구분 (신규)
- 성지를 "실제방문확인"과 "팬커뮤니티성지" 두 타입으로 구분 (레벨이 아니라 타입 차이)
- **성지 제보(UV-SPOT-04) 필드 추가**: 성지 타입 선택(실제방문확인/팬커뮤니티성지). 실제방문확인 선택 시 근거자료(기사 링크/소속사 공식 SNS/영상 캡처 등) 첨부 필드 필수 노출
- **검증**: 실제방문확인 건은 어드민 승인 큐(ADM-SPOT-03)에서 근거자료 기반으로 별도 심사
- **스코어 차등**: 실제방문확인 성지에서의 인증은 +1점 고정 보너스 (팬커뮤니티성지는 기존 조합 점수 1.0~2.5점 그대로)
- **시각 구분**: 지도 핀·랭킹 뱃지 등에서 실선/점선 테두리 또는 별도 뱃지로 구분 (1차안, 디자인 반영 단계에서 디벨롭 예정)
- 타입 명칭(실제방문성지/팬커뮤니티성지 등 팬덤 톤에 맞는 애칭)도 디자인 단계에서 확정

### 3-3. 플로팅 CTA 카피 변경
- 기존: "📸 땅 뺏어오기"
- 변경: "📸 발자국 남기기"

### 3-4. 점유율/성과 표현 톤 변경
- 기존: 승패/전황 중계 톤 (예: "역전", "점령")
- 변경: 동행/누적 뉘앙스로 (지도 탭 한정. 점령보드 탭은 경쟁 톤 유지)

### 3-5. 무소속(최애 미지정) 유저 진입 시
- 빈 지도나 강제 팝업 대신 "탐색 모드"를 기본값으로 — 여러 팬덤 성지가 섞인 채 인기순/거리순으로 노출
- 상단에 비침습적 넛지 배너: "관심있는 아티스트를 선택하면 발자취를 따라갈 수 있어요" + 인기 팬덤 칩 바로 선택
- 방문 인증 시 팬덤을 필수값으로 선택하도록 인증 화면이 이미 수정됨 → 무소속 상태에서의 인증 자체는 발생하지 않음 (기존 열린 질문 해결됨)

## 4. 점령보드(UV-WAR-01) 세부 변경사항
- 기존 구성(구별 점령 4색, 뒤집힘 타임라인, 경합구 Top3, 기여하기 CTA) 유지
- 지도 탭에서 빠진 "구별 점령 색칠"의 역할을 이 탭이 전담
- 경쟁적 게임 언어(역전/점령 등) 유지 — 이 탭에 들어온 유저는 이미 경쟁 콘텐츠를 보려는 의도가 있으므로

## 5. 랭킹(UV-RANK-01/02) 세부 변경사항
- "개인/팬덤" 서브탭 중 "팬덤" 서브탭 제거 — 팬덤 간 비교는 점령보드가 공간적으로 이미 담당
- 개인 랭킹만 남기고, 기간 필터(전체 누적/주간) 추가 — 신규 유저도 주간 랭킹에서 기회를 잡을 수 있도록
- 개인 누적점수 계산에 실제방문지 +1점 보너스 반영
- 기존 "상세 스펙 문서 없음" 플래그 중 이 부분(탭 구성)은 이번 논의로 해소됨

## 6. 체크리스트(`fw-check`) 업데이트 필요 항목
- UV-MAIN-01: "25개 구 GeoJSON 폴리곤 — DOMINATED/COMPETING/NEUTRAL/REVERSED 4상태 색상" 항목 삭제
- UV-MAIN-01: "플로팅 CTA [📸 땅 뺏어오기]" → "[📸 발자국 남기기]"로 교체
- UV-MAIN-01: 신규 항목 — "내 최애 성지 핀 표시 (방문/미방문 상태 구분, 실제방문확인/팬커뮤니티성지 타입 구분)"
- UV-MAIN-01: 신규 항목 — "무소속 유저 탐색모드(전체 팬덤 성지 인기·거리순 혼합) + 팬덤 선택 넛지 배너"
- UV-SPOT-04: 신규 항목 — "성지 타입 선택(실제방문확인/팬커뮤니티성지) + 실제방문확인 선택 시 근거자료 첨부 필수"
- UV-VERIF-02: 신규 항목 — "실제방문확인 성지 인증 시 +1점 고정 보너스 적용"
- UV-RANK-01: "개인/팬덤 탭 전환(추정)" → "개인 랭킹 단일 구성 + 기간 필터(전체/주간)"로 수정, 하단 "상세 스펙 문서 없음" 경고 해제

## 7. 열린 질문 (확정 필요)
- 무소속 유저 탐색 모드 정렬 기준: 단순 거리순으로 시작할지, 이벤트형(D-day 임박순)/상설형(누적 인증순) 이원화까지 갈지
- 팬덤 선택 넛지 배너 노출 빈도: 세션당 1회 vs 앱 실행마다 재노출 등
- 성지 타입(실제방문확인/팬커뮤니티성지) 최종 명칭 — 디자인 반영 단계에서 확정
- 실제방문확인 근거자료 심사 기준 상세(인정 자료 유형, 반려 시 이의제기 프로세스 등) — 어드민 플로우 별도 스펙 필요
- 지도 탭 감정적 페이오프 상세 구현(동행형 메인 UI가 구체적으로 어떤 비주얼인지 — 사진 중심/무드 중심 등) — 디자인 단계에서 이어서 논의
